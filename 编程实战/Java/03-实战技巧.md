# Java：实战技巧

## 分层别糊

- **Controller**：参数校验、鉴权上下文、DTO 进出；不写业务、不直接拼 SQL
- **Service**：事务边界、业务规则、编排
- **Mapper/Repository**：只访问数据
- 跨层传输：入参 Command/Query、出参 DTO/VO；别直接把 Entity 甩给前端

## 事务

- `@Transactional` 默认只回滚 **RuntimeException**；受检异常要 `rollbackFor`
- 同类自调用事务失效（代理）；抽到另一个 Bean 或用 Aspect 暴露的自注入（慎）
- 只读查询加 `readOnly=true`；长事务拆小，别包住远程 HTTP
- 和 DB 八股对照：隔离级别、脏读幻读见 `/workspace/面试八股/`

## 接口与兼容

- URL 稳定；字段只增不改义；删除用废弃期
- 统一响应：`{code,message,data}`；错误码表文档化
- 幂等：支付/下单用唯一键或 Token；重试安全

## 配置与安全

- 密钥走环境变量/密钥管理，不进 git
- 生产关 Swagger 或鉴权；Actuator 端点收敛
- SQL 防注入：预编译；动态表名白名单

## 性能直觉

- 避免 N+1：批量查、JOIN、或缓存
- 分页必带上限；深分页见面试八股「深分页」
- 线程池隔离：核心业务 vs 异步通知分开
- 连接池大小 ≈ 并发 ×（等待/服务时间）粗估，压测调

## 协作

- 日志带 `traceId`；关键写操作打 audit
- 代码评审看：空指针路径、事务、资源关闭、权限
