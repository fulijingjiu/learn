# Java：常用框架（怎么选 + 核心概念 + 口述）

## 怎么选（一句话）

| 场景 | 选型 |
|---|---|
| 新业务 HTTP API / 微服务起点 | **Spring Boot**（几乎默认） |
| Web 层（路由、参数、拦截） | Spring MVC（Boot 已内嵌） |
| SQL 多、要写清语句、DBA 友好 | **MyBatis** / MyBatis-Plus |
| 领域模型强、少手写 SQL | **JPA/Hibernate**（或 Spring Data JPA） |
| 只要极简 IOC | 别重复造轮子，仍优先 Boot |

中小团队：**Boot + MyBatis-Plus** 最常见；领域复杂可 JPA。别在一个模块混两套 ORM 除非有迁移计划。

## Spring / Spring Boot 核心概念

- **IoC / DI**：对象交给容器创建注入，类之间不 `new` 死依赖
- **Bean**：容器管理的对象；单例默认
- **AOP**：横切（日志、事务、权限）用切面，不污染业务
- **自动配置**：classpath 有什么就配什么；`starter` 依赖即能力
- **MVC 链路**：DispatcherServlet → HandlerMapping → Controller → 返回 JSON/视图

## MyBatis vs JPA（口述）

- **MyBatis**：SQL 可见可控，复杂报表/优化友好；XML 或注解映射
- **JPA**：面向对象，CRUD 快；复杂查询/性能调优成本更高，易「魔法 SQL」
- 面试加分：二者都能用事务（Spring `@Transactional`）；脏数据问题仍要懂隔离级别（见面试八股）

## 面试口述模板

「我们用 Spring Boot 起服务，Web 用 Spring MVC。持久层选 MyBatis，因为报表 SQL 多、要可控。事务交给 Spring 声明式，边界在 Service。配置用 yml，分环境。」
