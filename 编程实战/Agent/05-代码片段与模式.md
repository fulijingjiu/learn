## 1. Tool Calling 循环（核心）

```python
# 伪代码：与具体 SDK 无关
messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": user_q}]
TOOLS = [search_orders, get_sku]  # 真实函数 + JSON schema

for _ in range(MAX_ITER):
    resp = llm.chat(messages, tools=TOOLS)  # 模型可能返回 tool_calls
    if not resp.tool_calls:
        return resp.content  # 最终自然语言答案

    messages.append(resp.as_message())
    for call in resp.tool_calls:
        # 危险：这里必须校验工具名与参数！
        result = dispatch(call.name, call.args)  # 你的代码执行工具
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": stringify(result),
        })
raise RuntimeError("exceeded max iterations")
```

要点：循环在你进程里；模型只「提议」调用，**真正执行权在你**。

## 2. ReAct 口述

```
Thought: 用户要查订单 123 状态
Action: search_orders({"order_id": "123"})
Observation: {"status": "shipped", "eta": "2026-11-07"}
Thought: 已有足够信息
Final Answer: 订单 123 已发货，预计 11-07 到。
```

现代 API 多用结构化 `tool_calls`，不一定输出 Thought 文本，但逻辑相同。

## 4. 写操作必须拦截

```python
WRITE_TOOLS = {"refund", "send_email"}

def dispatch(name, args):
    if name in WRITE_TOOLS and not human_approved(name, args):
        return {"error": "need_approval", "preview": args}
    return TOOL_IMPL[name](**args)
```

## 5. 和框架的对应关系
