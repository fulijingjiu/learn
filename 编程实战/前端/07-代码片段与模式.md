# 代码片段与模式

## 1. 错误边界（类组件，React 仍需要）

```tsx
import { Component, type ReactNode } from "react";

export class ErrorBoundary extends Component<
  { children: ReactNode; fallback?: ReactNode },
  { error: Error | null }
> {
  state = { error: null as Error | null };
  static getDerivedStateFromError(error: Error) {
    return { error };
  }
  render() {
    if (this.state.error) {
      return this.props.fallback ?? <p>出问题了</p>;
    }
    return this.props.children;
  }
}
```

## 2. 数据请求（React Query 味道）

```tsx
import { useQuery } from "@tanstack/react-query";

export function useUser(id: string) {
  return useQuery({
    queryKey: ["user", id],
    queryFn: () => fetch(`/api/users/${id}`).then(r => {
      if (!r.ok) throw new Error("load user failed");
      return r.json();
    }),
    enabled: Boolean(id),
  });
}
```

## 3. 受控输入防抖搜索

```tsx
import { useEffect, useState } from "react";

export function useDebounced<T>(value: T, ms = 300) {
  const [v, setV] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setV(value), ms);
    return () => clearTimeout(t);
  }, [value, ms]);
  return v;
}
```

## 5. Fastify + schema 一句

```ts
import Fastify from "fastify";
const app = Fastify();
app.get("/items/:id", {
  schema: { params: { type: "object", required: ["id"], properties: { id: { type: "string" } } } },
}, async (req) => ({ id: (req.params as { id: string }).id }));
await app.listen({ port: 3000 });
```

## 9. 片段不是生产方案：逐段补上使用边界

| 片段 | 必须补的边界 | 建议验证 |
|---|---|---|
| ErrorBoundary | 不捕获任意异步/事件异常；提供重试或重挂载策略、脱敏上报 | 子组件 render 抛错、路由切换后恢复 |
| useUser | QueryClientProvider、响应运行时校验、超时/取消、权限语义 | id 变化、404、慢请求、卸载 |
| useDebounced | 只推迟值变化，不是请求取消/服务端限流 | 连续输入、ms 变化、卸载无残留定时器 |
| Express / Fastify | 输入体积/格式、鉴权、错误处理、日志、关闭流程 | 非法入参、下游超时、SIGTERM |
| antd 表单 | 提交中状态、错误保留、重复提交/后端幂等 | 双击、校验失败、提交失败后重试 |
| lazy + Suspense | 默认导出匹配，加载失败需错误边界 | chunk 失败、旧资源被清理、慢网 |
| LongLabel story | 需承接该组件的 Story 类型和 meta | 窄屏、键盘、tooltip/换行策略 |

### useUser：把取消信号传到 fetch

下面承接前面的 useUser 模式，`response.json()` 的结构仍需项目自己的 schema 校验：

```tsx
queryFn: async ({ signal }) => {
  const response = await fetch(`/api/users/${encodeURIComponent(id)}`, { signal });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
},
```

这个片段应放在 useQuery 配置对象内部，不是独立可执行模块。signal 允许查询层在取消时中止请求，但取消读请求不代表撤销服务端已执行写操作。关键 ID 若为 64 位数据库整数，用字符串从接口传递到前端，避免 Number 精度损失。

### 表单：谁拥有提交状态？

调用层应返回 Promise 或显式管理 pending/error，防止 onFinish 一触发就关闭弹窗。按钮 loading 负责视觉反馈，禁用负责减少误操作，后端唯一约束/幂等负责真正一致性；三者职责不同。服务端字段错误应映射到对应字段，系统错误才放全局提示。

## 常见坑

- 从 `r.json()` 写 `as User` 当成安全校验；类型断言不会检查真实字段。
- queryKey 少了租户、语言或筛选，复用到错误数据；修改后不失效相关列表又显示旧值。
- 把 ErrorBoundary 的“重试”仅实现为再渲染同一个坏输入；需要清理错误状态并修正输入/重新请求。
- Express 版本不同，async 处理器异常传播方式不同；确认当前主版本，不靠未处理 rejection 处理请求。
- 直接复制顶层 await 片段到不支持的 CJS/构建目标，或没安装对应包/Provider。
- 代码示例的 localhost、路径和权限不是部署配置，不将示例密码/Key 当真实默认值。

## 面试口述

> 我把代码片段当最小机制示例，接项目时会补生命周期、输入输出校验和失败恢复。请求取消要传 signal，查询缓存键要覆盖真正影响结果的参数，类型断言不能代替运行时校验。错误边界、表单 loading 和后端幂等各管不同层，不能互相替代。最后用慢网、错误响应、重复提交和卸载场景验证，而不只跑一次成功路径。
