# 05 部署实战技巧

## 面试口述

好的部署是**可重复、可回滚、可观测**：镜像带版本号、配置外置、健康检查、发布可一键回退。小团队常见路径：本机 Docker Compose → 单机 Nginx+容器 → 再上 K8s/Rancher。

---

## 典型路径对照

| 阶段 | 做法 | 适合 |
|---|---|---|
| 开发本机 | Compose 起 app+db+redis | 本地联调 |
| 单机/小项目 | Docker + Nginx 反代 + systemd 或 compose | 早期上线 |
| 多副本 | K8s Deployment + Service + Ingress | 要弹性与滚动更新 |
| 多集群/多团队 | Rancher 管集群与权限 | 中大型 |

---

## 可操作发布清单（单机容器版）

1. **构建**：`docker build -t registry.example.com/app:1.2.3 .`  
2. **推送**：登录私有仓后 `docker push ...`  
3. **服务器拉取**：跳板机进业务机，`docker pull`  
4. **停旧启新**（或蓝绿/滚动）：  
   ```bash
   docker stop app && docker rm app
   docker run -d --name app --restart=unless-stopped \
     -p 127.0.0.1:8080:8080 \
     --env-file /opt/app/env.prod \
     -v /opt/app/logs:/app/logs \
     registry.example.com/app:1.2.3
   ```  
5. **Nginx reload**（若改了 upstream）  
6. **冒烟**：`curl -I https://api.example.com/healthz`  
7. **保留上一版本镜像标签**，出问题立刻切回  

### 配置与密钥

- 配置：文件 / 环境变量 / ConfigMap  
- 密钥：环境变量或密钥管理（Vault 等），**不要写死在镜像**  
- `.env` 权限：`chmod 600`，仅部署用户可读  

### 零停机思路（口述）

- 两实例 + Nginx upstream，先升 B 再摘 A  
- K8s：`rollingUpdate` + readinessProbe  
- 数据库变更：先兼容旧代码的迁移，再发应用（expand/contract）

### CI/CD 最小闭环

```
git push → 跑测试 → build 镜像 → 推仓库 →（人工/自动）部署 → 健康检查
```

## FinalShell / 跳板机在发布中的位置

- 仅作**通道**：上传脚本、看日志、临时隧道  
- 真正制品应来自镜像仓库，避免「本机 scp 一个 jar 到生产」成为唯一方式  
- 生产变更尽量工单 + 审计（堡垒机）

## 检查表

- [ ] 版本号可追溯（git sha / semver）  
- [ ] 回滚演练过一次  
- [ ] 磁盘与日志轮转（`logrotate`）已开  
- [ ] 监控：进程存活、HTTP 探活、磁盘、证书过期
