# 三库对比速查

> MySQL · PostgreSQL · SQL Server  
> 临考翻这张表；细节回各自专题。  
> 未标注处均为**常见说法 / 一般默认**，以实际版本与配置为准。

---

## 1. 产品与选型

| 维度 | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|
| 开源许可 | 开源（社区版 GPL 等；商业另有） | 开源（宽松许可，常见说法） | 商业为主（有免费 Express 等） |
| 厂商 / 生态 | Oracle 公司社区版；MariaDB 同源分支叙事 | 社区驱动 | 微软 |
| 典型选型理由 | 互联网标配、运维与招人多、中间件成熟 | 复杂 SQL、JSONB、GIS、扩展强 | .NET / Windows / 企业授权已有 |
| 默认引擎或组织 | **InnoDB** 插件引擎 | 单一内核；堆表+索引 | 关系引擎；聚集索引表常见 |

---

## 2. 事务与隔离

| 维度 | MySQL (InnoDB) | PostgreSQL | SQL Server |
|---|---|---|---|
| 默认隔离级别 | **可重复读 RR** | **读已提交 RC** | **读已提交 RC** |
| 脏读（默认） | 一般不会 | 一般不会 | 一般不会 |
| MVCC | 有（undo + Read View） | 有（元组多版本 + VACUUM） | 可选快照类隔离加强版本读（RCSI 等，常见说法） |
| 幻读相关 | RR + 间隙锁 / 临键锁，多数场景可抑制 | 视隔离级别；Serializable 有 SSI 等 | 默认 RC 下仍可能；可调高隔离或用快照 |

三个坏现象解释见：[`MySQL-事务隔离级别.md`](./MySQL-事务隔离级别.md)

## 3. 索引与表组织

| 维度 | MySQL (InnoDB) | PostgreSQL | SQL Server |
|---|---|---|---|
| 数据组织 | **聚簇**：主键叶子是整行 | 堆表为主，索引指向元组 | **聚集索引**决定行序；也可堆表 |
| 二级索引 | 叶子存主键，常需**回表** | 索引存元组标识，可能再找堆 | 非聚集指向聚集键/行 ID，可能回表 |
| 常见索引类型 | 以 B+Tree 为主 | B-Tree、**GIN、GiST、BRIN** 等 | 聚集 / 非聚集；列存储索引等（进阶） |
| 联合索引最左前缀 | 重要（见专题） | B-Tree 联合索引同样讲究左前缀思路 | 同样有复合索引列顺序问题 |

专题：[`MySQL-B+树索引.md`](./MySQL-B+树索引.md) · [`MySQL-聚簇与非聚簇索引.md`](./MySQL-聚簇与非聚簇索引.md) · [`MySQL-最左前缀原则.md`](./MySQL-最左前缀原则.md)

## 4. 锁（极简）

| 维度 | MySQL (InnoDB) | PostgreSQL | SQL Server |
|---|---|---|---|
| 默认倾向 | 行级锁 + 间隙/临键（RR） | 行级锁为主 | 行/页/表；可能锁升级 |
| 特色名词 | 意向锁、间隙锁、临键锁 | 与 MVCC/VACUUM 常一起考 | NOLOCK、RCSI、死锁图 |

---

## 5. 自增 / 主键生成

| 维度 | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|
| 常见写法 | `AUTO_INCREMENT` | `SEQUENCE` / `serial` / `GENERATED AS IDENTITY` | `IDENTITY` |
| 跳号 | 可能（常见说法） | 序列一般不回滚，易跳号 | 可能跳号（常见说法） |

---

## 6. 分页语法（口述够用）

| 库 | 常见写法 |
|---|---|
| MySQL | `LIMIT offset, count` 或 `LIMIT count OFFSET offset` |
| PostgreSQL | `LIMIT count OFFSET offset` |
| SQL Server | `OFFSET n ROWS FETCH NEXT m ROWS ONLY`；老项目 `ROW_NUMBER()` |

深分页都慢：大 offset 要优化（延迟关联、键续传等），三库同理。

---

## 7. 字符串与大小写（常见坑）

| 维度 | 常见说法 |
|---|---|
| MySQL | 是否大小写敏感看**排序规则 collation** 与操作系统/配置；很多人默认环境对表名/库名不敏感 |
| PostgreSQL | 未加引号标识符会折成小写；大小写敏感比较看排序规则 / `citext` 等 |
| SQL Server | 默认常不区分大小写（视 collation）；标识符规则与 MySQL/PG 不同 |

面试一句：\*\*别假设三库字符串比较规则一样，看 collation。\*\*

## 8. 复制 / 高可用（概念一词）

| 库 | 常提概念 |
|---|---|
| MySQL | binlog 主从；半同步；Group Replication 等 |
| PostgreSQL | 流复制；逻辑复制 |
| SQL Server | **Always On** 可用性组（AG） |

---

## 9. 临考口述模板

**被问「三库怎么选」：**  
> 互联网、招人多、中间件熟 → MySQL。要复杂查询、JSONB、GIS、扩展 → PostgreSQL。团队 .NET/Windows、已有微软授权 → SQL Server。

**被问「默认隔离」：**  
> MySQL InnoDB 默认可重复读；PostgreSQL 和 SQL Server 默认读已提交。

**被问「聚簇」：**  
> InnoDB 和 SQL Server 都常把数据按聚集/主键排；PG 偏堆表加索引，更新多要操心 VACUUM。
