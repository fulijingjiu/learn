# MySQL 存储引擎：InnoDB vs MyISAM

> 学习笔记 · 面试八股

## 这两个名字是什么

- **InnoDB**：Innobase 公司做的引擎，后被 Oracle 收购，现为 MySQL **默认引擎**。没有固定中文意译，口语叫「InnoDB 引擎」。
- **MyISAM**：MySQL 自带的老引擎。名字来自 **ISAM**（Indexed Sequential Access Method，索引顺序访问方法），前面加了 My。口语叫「MyISAM 引擎」。
- 面试说法：它们是 **存储引擎 / 表引擎**，决定表怎么存、怎么锁、支不支持事务。

## 一句话比喻

把数据库想成一本公用账本：

| | MyISAM | InnoDB |
|---|---|---|
| 改账 | 整本账本只能一个人改，别人要等 | 只锁正在改的那一行，别人改别的行没事 |
| 断电 | 改到一半可能写花 | 有日志，能把账补回来 |
| 事务 | 不支持 | 支持（要么全成功，要么全撤销） |

## 对比表（面试常答）

| 点 | InnoDB | MyISAM |
|---|---|---|
| 事务 | 支持（ACID） | 不支持 |
| 锁 | 行级锁，并发更好 | 表级锁，写多易堵 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | 有 redo/undo，更稳 | 容易坏表 |
| 全文索引 | 较新版本也支持 | 更早支持 |
| 存储 | 数据与索引同表空间 | `.MYD`（数据）+ `.MYI`（索引） |

## 怎么选

- **业务表几乎都用 InnoDB**（订单、用户、库存、钱相关）。
- MyISAM：只读、无事务的统计表偶尔还能见到；**新项目别用**。

## 关系型 vs 非关系型（顺带）

- **关系型（MySQL 等）**：有表、字段、外键；适合要强一致、要联表查的数据（订单、用户、库存）。
- **非关系型（MongoDB、Redis 等）**：结构更松；适合缓存、日志、文档、高并发读写，不一定要强事务。
- **常见搭配**：业务主数据用 MySQL，热点和会话用 Redis。

# 事务隔离级别

## 三个坏现象

- **脏读**：读到别人还没提交的数据，对方一回滚你就读错了。
- **不可重复读**：同一事务里两次读同一行，中间被人改了，结果不一样。
- **幻读**：同一条件两次查，中间被人插入/删除了行，行数变了（像出现幻觉）。

## 四级（从松到严）

| 级别 | 脏读 | 不可重复读 | 幻读 | 一句话 |
|---|---|---|---|---|
| 读未提交 Read Uncommitted | 会 | 会 | 会 | 几乎不用 |
| 读已提交 Read Committed | 不会 | 会 | 会 | Oracle 默认 |
| 可重复读 Repeatable Read | 不会 | 不会 | 基本不会* | **MySQL InnoDB 默认** |
| 串行化 Serializable | 不会 | 不会 | 不会 | 最严，并发差 |

\* InnoDB 用 MVCC + 间隙锁，RR 下多数幻读也能避免。

## 怎么记 / 怎么选

- 级别越高越安全，锁/等待越多。
- 日常业务默认 **RR** 就够。
- 要「每次读最新已提交」才用 **RC**。
