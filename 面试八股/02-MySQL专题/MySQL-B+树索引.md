# 索引为什么用 B+ 树

> 学习笔记 · 面试八股

## 一句话

B+ 树高度低、查询快、对磁盘友好；叶子有序且链表相连，适合范围查。

## 对比二叉树

- 二叉树一层只分两边，数据一多**树很高**。
- 高度 ≈ 磁盘 IO 次数，高了就慢。
- B+ 是多路平衡树：一个节点塞很多键，**树更矮**，IO 更少。

## 对比哈希

| | B+ 树 | 哈希 |
|---|---|---|
| 等值查询 | 快 | 通常更快 |
| 范围查询（`BETWEEN`、排序） | 支持（叶子有序 + 链表） | **不支持** |
| 最左前缀等场景 | 适合 | 不适合 |

所以 InnoDB 默认用 B+ 树做索引，不是哈希。

## 对磁盘友好

- 数据库主要瓶颈在磁盘 IO，不是 CPU。
- B+ 节点大小常对齐页（如 16KB），一次读一页进很多键。
- 非叶子节点只存键和指针，不存整行，一层能放更多路，进一步压低高度。

## 面试口述版

「索引用 B+ 树，因为多路平衡、树矮、磁盘 IO 少；叶子有序串链表，范围查询方便。二叉树太高；哈希不能范围查。」
