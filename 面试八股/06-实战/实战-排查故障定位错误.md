# 实战 · 排查故障与定位错误

> 连接失败、锁与死锁、主从延迟、磁盘满、慢 SQL、错误码、日志思路、缩小范围步骤。  
> 相关：[`隔离级别`](./MySQL-事务隔离级别.md) · [`分析数据`](./实战-分析数据.md) · [`开发技巧`](./实战-开发实现技巧.md)

## 0. 通用缩小范围（先做这个）

**步骤清单**

1. **复现**：能否稳定复现？只读还是写入？哪个环境（本地/测试/生产）？  
2. **边界**：整库挂了，还是某条 SQL / 某个接口？从何时开始（发布、扩容、促销）？  
3. **分层**：应用报错 → 连接池 → 网络 → 数据库实例 → SQL / 锁 / 磁盘。  
4. **证据**：完整报错原文、时间点（含时区）、request id、当时 SQL、影响面。  
5. **止血**：限流、切从库读、杀长事务、扩容磁盘——先保业务，再根因。  
6. **根因**：改配置/SQL/索引/代码；写清「为什么好了」，避免只重启。

**口述短句**

> 先复现和划边界，再按应用→连接→库→SQL/锁/磁盘分层取证；止血和根因分开做。

## 1. 连接失败

**常见原因清单**

- 地址/端口/库名/账号错；白名单或安全组未放行。  
- 密码过期、权限不足（能连上但某库拒绝）。  
- 连接数打满（`Too many connections`）：池过大或泄漏。  
- TLS/SSL 要求不匹配；超时过短。  
- 实例宕机、磁盘满导致拒绝写入甚至异常。

**排查步骤**

1. 同一机器用官方客户端/`mysql`/`psql`/`sqlcmd` 直连，排除应用配置。  
2. 看报错全文（认证失败 vs 超时 vs 拒绝连接，含义不同）。  
3. 查当前连接数与上限；查应用池是否泄漏。  
4. 查网络与白名单；查实例监控是否存活、磁盘是否满。

**口述短句**

> 连接问题先用命令行直连定性：认证、网络、连接打满还是实例异常，再对应用池和白名单。

## 2. 锁等待 / 死锁

**现象**

- 接口卡住、更新超时；日志里 lock wait timeout。  
- 死锁：一事务被回滚，日志有 deadlock。

**MySQL 思路（示意）**

- 看谁在等：`SHOW ENGINE INNODB STATUS\G`（近期死锁信息）。  
- 查进程：`SHOW PROCESSLIST` / `performance_schema` 相关表。  
- 找到持锁事务：是否长事务、没提交、在事务里干别的。

**处理步骤**

1. 确认阻塞链：谁持锁、谁等待、等什么行/表。  
2. 能杀则杀无用长事务（先评估业务）。  
3. 代码：缩小事务、统一加锁顺序、必要索引避免锁升级/锁过多行。  
4. 死锁：业务可重试一次；长期靠消除冲突顺序。

**口述短句**

> 锁问题先画阻塞链，优先处理长事务；死锁靠统一加锁顺序加有限次重试，而不是盲目加大超时。

## 3. 主从延迟

**现象**

- 写后立刻读从库，读到旧数据；监控 Replication lag 升高。

**常见原因**

- 从库硬件弱；大事务/大批量写；无主键表的行复制；从库自身慢查询占资源。

**步骤**

1. 看 lag 指标与错误复制线程状态。  
2. 是否刚跑过大导入/DDL。  
3. 业务侧：强一致读走主库；可延迟读接受则保持读从。  
4. 长期：拆大事务、从库升配、表有主键。

**口述短句**

> 主从延迟时，强一致读主库；根因常是大事务或从库资源不足，而不是「随机抽风」。

---

## 4. 磁盘满

**现象**

- 写入失败、binlog/redo 写不进、实例只读或崩溃。

**步骤**

1. 确认哪个盘：数据、日志、临时目录、备份目录。  
2. 止血：清过期 binlog/日志（按规范）、扩容、挪备份。  
3. 根因：增长来自数据、日志、临时文件还是备份没清。  
4. 设监控与水位告警，避免下次被动。

**口述短句**

> 磁盘满先分清数据盘还是日志盘，止血扩容或按规范清理，再查增长来源并加水位告警。

## 5. 慢 SQL（线上变慢）

**步骤**（与 [`分析数据`](./实战-分析数据.md) 衔接）

1. 慢日志 / APM 抓到具体 SQL。  
2. `EXPLAIN`：索引是否失效、行数是否暴涨。  
3. 数据量是否突增、统计是否过期、有无锁等待冒充「慢」。  
4. 改写 SQL / 加索引 / 限流；大查询拆到离线。

**口述短句**

> 慢 SQL 先拿全文和计划，区分没索引、数据涨、统计过期还是锁等待，再改。

## 6. 错误码怎么查

**步骤**

1. **完整保存**报错：错误码 + SQLSTATE + 英文/中文消息 + 当时 SQL。  
2. 用官方文档按错误号查（MySQL Error Codes、PostgreSQL SQLSTATE、SQL Server 消息编号）。  
3. 区分：语法/权限/约束冲突（业务可预期）vs 资源/崩溃（运维向）。  
4. 约束冲突（重复键、外键）：回到业务幂等与校验，而不是只「重试到成功」。

**口述短句**

> 报错要留全文和错误号，对照官方文档；约束类走业务幂等，资源类走容量与运维。

## 7. 日志在哪（思路，路径因安装而异）

| 类型 | 一般看什么 |
|---|---|
| 错误日志 | 启动失败、崩溃、严重 InnoDB 错误 |
| 慢查询日志 | 超时 SQL |
| 二进制日志 / WAL | 复制、点播恢复（慎动） |
| 审计/通用日志 | 谁执行了什么（开销大，临时开） |
| 应用日志 | 连接串脱敏后的异常栈、事务边界 |
| 云厂商控制台 | 监控、慢 SQL、错误日志聚合 |

**原则**：先应用日志时间线，再库错误日志，再慢日志/锁状态；路径以本机配置/`SHOW VARIABLES`/云文档为准。

**口述短句**

> 日志排查按时间线：应用异常 → 库错误日志 → 慢日志与锁；具体路径查配置，不硬背默认目录。

## 8. 场景速查表

| 症状 | 优先怀疑 | 先做 |
|---|---|---|
| 连不上 | 网络/账号/连接满/实例挂 | 命令行直连 |
| 卡住超时 | 锁等待、慢 SQL、池耗尽 | processlist + 锁/慢日志 |
| 偶发旧数据 | 读从延迟、缓存 | 是否读从、lag |
| 写入失败 | 磁盘、只读实例、权限、约束 | 错误码全文 |
| 死锁回滚 | 并发更新同序冲突 | 死锁日志 + 加锁顺序 |
| 发布后变慢 | 新 SQL、索引变化、统计 | 对比发布前后 Top SQL |

## 9. 故障记录模板（方便复盘 / 面试讲项目）

- 时间（时区）与影响面  
- 现象与报错原文  
- 已做止血  
- 根因（一句话）  
- 永久修复与预防（监控/限流/索引/代码）
