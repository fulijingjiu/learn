## 一、关系型 vs 非关系型

### 关系型（RDBMS）

- 有**表、字段、主键、外键**，数据结构化。
- 强事务（ACID），适合订单、用户、库存、账务。
- 典型：MySQL、PostgreSQL、SQL Server、Oracle。

### 非关系型（NoSQL，常见几类）

| 类型 | 代表 | 适合 |
|---|---|---|
| 键值 Key-Value | Redis、DynamoDB | 缓存、会话、计数 |
| 文档 Document | MongoDB | 内容、日志、灵活 schema |
| 列族 Column-family | Cassandra、HBase | 海量写入、时序宽表 |
| 图 Graph | Neo4j | 社交关系、推荐路径 |

### 面试口述版

> 业务主数据一般用关系型，要联表、要强一致；缓存和热点用 Redis；文档型适合结构常变的内容。常见搭配是 **MySQL/PG 存业务 + Redis 做缓存**。

## 二、三库定位一览

| 维度 | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|
| 开源 / 商业 | 开源（Oracle 公司维护社区版；另有 MariaDB） | 开源（BSD 风格许可，社区驱动） | 微软商业产品（有 Express 等免费版） |
| 典型定位 | Web / 互联网最常见，运维生态大 | 「最像正经数据库」的开源库，复杂查询、扩展强 | Windows / .NET 企业栈首选 |
| 默认存储 / 架构特点 | 插件式存储引擎；默认 **InnoDB** | 单一内核，表即堆表+索引；扩展（Extension）丰富 | 关系引擎一体；与 Windows、AD、SSIS/SSRS 等微软生态紧 |
| 默认隔离级别（一般情况） | InnoDB：**可重复读 Repeatable Read（RR）** | **读已提交 Read Committed（RC）** | **读已提交 Read Committed（RC）** |
| 适用场景 | 电商、后台、中小型业务、读写分离 | GIS、分析型 SQL、JSON、科研/复杂业务、云原生开源栈 | 企业内部系统、ERP、.NET 项目、强 Windows 运维 |
| 常见面试对比点 | 引擎、B+、锁与间隙锁、主从 binlog | MVCC + VACUUM、多种索引、JSONB、进程模型 | 锁与隔离提示、聚集索引表、执行计划、Always On |

### 面试口述版

> MySQL 是互联网默认选项，InnoDB、主从很熟；PostgreSQL 开源里功能更全，复杂 SQL、JSON、扩展好；SQL Server 偏微软企业栈。.NET 或 Windows 运维多选 SQL Server，云上开源业务多选 MySQL 或 PG。

---

## 三、选型常问「为什么选它」

- **选 MySQL**：招人多、文档多、中间件（分库分表、同步）成熟，默认 RR + InnoDB 够用。
- **选 PostgreSQL**：要标准 SQL、窗口函数、GIS（PostGIS）、JSONB、自定义类型/扩展；讨厌「引擎分裂」叙事。
- **选 SQL Server**：团队已是 .NET / Azure / Windows；需要与 Active Directory、Reporting Services 等集成；公司已买微软授权。
